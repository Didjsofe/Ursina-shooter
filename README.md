# LAN Deathmatch (Python 3.12 + Ursina)

<p align="center"><img src="logo.ico" alt="LAN Deathmatch" width="240"></p>

Локальный сетевой FPS для одной LAN. Единственный режим — Deathmatch, победа при 100 убийствах в одном матче. Сервер запускается отдельным консольным процессом и не требует сторонних библиотек; клиент использует Ursina.

## Архитектура и протокол

```text
client.py (Ursina) ── TCP, JSON + LF ── server.py ── SQLite players.db
```

Каждая TCP-запись — UTF-8 JSON-объект с завершающим `\n`; границы `recv()` не считаются границами сообщений. `shared/protocol.py` разбирает неполные/склеенные кадры. Клиент отправляет `login`, ограниченные `input` (forward/side/yaw/pitch/dt), `shoot`, `pause` и `stats`. Сервер сам проверяет скорость/границы, скорострельность, разброс, направление луча, HP, убийства, оружие, таблицу матча и респавн. Клиентские HP, координаты и урон не принимаются.

Пароли хэшируются PBKDF2-HMAC-SHA256 с индивидуальной случайной солью. Статистика аккаунта сохраняется в `players.db`; матчевые убийства и смерти хранятся отдельно в памяти сервера. HUD и TAB показывают текущую игру, поэтому новый матч начинается с нулевого счёта. Оружие меняется каждые 10 убийств текущего матча; параметры и цвета заданы в `shared/weapons.py`.

## Структура

```text
client.py                 запуск клиента
logo.ico                  иконка окна и клиентского EXE
logo.png                  логотип для README/GitHub
client/main.py             Ursina: вход, управление, HUD, событие клавиш
client/network.py          TCP-соединение и поток чтения
client/world.py            арена и удалённые игроки
server.py                  запуск сервера
server/main.py             SQLite, авторизация, матч, консоль, авторитетная логика
shared/constants.py        порт, лимиты, точки спавна
shared/protocol.py         кадрирование JSON по строкам
shared/weapons.py          10 уровней оружия
config.json                адрес сервера, порт и таймаут
```

## Установка и запуск на школьных ПК

Нужен Python 3.12, установленный для пользователя. Интернет нужен только один раз для установки Ursina на машине сборки; после этого клиент и сервер работают внутри LAN. На ПК сервера откройте терминал в папке проекта:

```powershell
python -m pip install ursina
python server.py
```

Сервер слушает `0.0.0.0:27015`. Для Windows Firewall создайте разрешение входящих TCP-соединений для Python/собранного EXE либо разрешите порт 27015 в настройках сети. Права администратора для Python не требуются, если школьная политика уже разрешает сетевые подключения приложений. Узнайте IPv4 сервера через `ipconfig` (например, `192.168.1.20`). В консоли сервера создайте аккаунты:

```text
server> create Alice password123
server> create Bob password456
server> startmatch
```

На клиентском ПК измените `server_ip` в `config.json` на IPv4 сервера. Запустите `python client.py`, войдите созданным логином/паролем. После успешного входа имя, пароль и IP запоминаются в JSON для следующего запуска; поля входа будут заполнены автоматически, затем достаточно нажать «Entrar». Пароль хранится в этом локальном JSON без шифрования. Для собранного EXE пользовательский конфиг хранится в `%LOCALAPPDATA%\LanDeathmatch\config.json`, чтобы его можно было записывать без прав администратора. Настройки подключения: `server_ip`, `port`, `connect_timeout`. Клиент может запускаться на нескольких ПК. Серверные команды: `create <username> <password>`, `delete <username>`, `list`, `ban <username>`, `unban <username>`, `kick <username>`, `resetstats <username|all>`, `addkills <username>` (добавляет 10 убийств для проверки прогрессии оружия), `startmatch`, `stopmatch`, `quit`.

## Управление

- WASD — движение, мышь — обзор, Shift — бег, Ctrl — присесть и уменьшить разброс, пробел — прыжок. Удержание ЛКМ — автоматическая стрельба; при пустом магазине сервер автоматически начинает перезарядку (R — вручную). Удерживайте ПКМ для индивидуального зума; AWP показывает специальную снайперскую сетку.
- Магазин и запас патронов проверяются сервером. Если `players.db` недоступна для записи, сервер копирует её в пользовательскую папку данных и продолжает работу. После обновления кода обязательно перезапустите `server.py`.
- Прицел находится в центре экрана; клавиша Enter отключает клиента и возвращает к форме входа.
- TAB — запрос/показ таблицы убийств и смертей текущего матча. Команда сервера `addkills <username>` добавляет тестовые фраги подключённому игроку и сразу обновляет счёт и оружие.
- ESC — поставить игру на паузу или вернуться в матч. На паузе курсор свободен, игрок неподвижен, не стреляет и не получает урон.
- Победитель показывается всем; следующий матч автоматически стартует через 10 секунд.
- Если сервер ещё не ввёл `startmatch`, игрок сразу попадает в свободную тренировку. Можно ходить и стрелять одному; урон и статистика в тренировке выключены. После серверной команды `startmatch` начнётся Deathmatch.

Клиентский интерфейс (форма входа, сообщения и HUD) отображается на испанском. В игре 10 уровней оружия, оружие меняется каждые 10 убийств. Правая кнопка мыши включает индивидуальное приближение для текущего оружия; у AWP появляется специальная сетка прицела. Арена немного компактнее предыдущей версии, без возвышенностей.

Счёт и статистика DEATHMATCH на экране — только текущий матч. При достижении 100 фрагов сервер объявляет победителя, через 10 секунд начинает следующую игру и сбрасывает у всех матчевые убийства, смерти и прогрессию оружия. Накопительная статистика аккаунта в SQLite сохраняется между матчами.

## Сборка клиента в EXE

Устанавливайте зависимости в пользовательскую среду сборочной машины:

```powershell
python -m pip install ursina pyinstaller
python -m PyInstaller --noconfirm --clean --workpath build_displayfix --distpath dist_displayfix LanDeathmatch.spec
```

Готовый EXE будет в `dist_displayfix\LanDeathmatch\LanDeathmatch.exe`. Переносите всю папку `LanDeathmatch` вместе с `_internal`, а не только EXE. Рядом с EXE положите `config.json`. Каталог `shared` и `client` PyInstaller соберёт как импортируемые модули. На клиентских ПК Python и права администратора не нужны. Сервер запускается отдельно командой `python server.py` и для него нужен Python 3.12.

## Границы этой версии

Это компактный LAN-прототип: игровой трафик идёт по одному TCP-соединению, поэтому при потерях пакетов TCP может задерживать обновления. Серверный raycast проверяет попадания по игрокам, а трассеры используют те же координаты и дистанцию, что и серверная проверка. Укрытия пока не блокируют лучи. Сервер ограничивает движение ареной и проверяет столкновения с укрытиями. Для использования в недоверенной сети следует добавить TLS/защиту канала и серверную проверку столкновений с картой. Арена рассчитана на 10 игроков. При старте матча игроки получают разные стартовые точки; после смерти сервер выбирает свободную случайную точку респавна. Прыжки и вертикальное перемещение считает сервер.
